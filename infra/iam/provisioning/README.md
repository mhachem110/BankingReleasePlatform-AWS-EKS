# Additive Banking provisioning proposals

Use the protected workflow and [infrastructure operations guide](../../OPERATIONS.md). These files are proposals, not installed policies. Preserve CloudOpsTrackerBootstrap, BankingReleasePlatformState, every existing attachment, all Retail/Banking trust and unrelated roles. The proposed service boundary is administrator-owned outside Terraform.

[review-manifest.json](proposed/review-manifest.json) lists exact canonical SHA256s, managed-policy sizes and unresolved inputs. The IAM-stage, boundary, state and optional read-only simulation proposals contain no unresolved identifiers. Platform/data templates must be finalized and reviewed against the actual protected plan before apply; never paste templates or infer authorization from offline validation.

Generate with `python scripts/infra/provisioner_policies.py --output artifacts/provisioner-review`. Optional exact inputs are --kms-key-arn, --vpc-id, --default-security-group-id, --operator-role-arn, --dev-alert-topic-arn and --prod-alert-topic-arn. Inputs are non-secret ARNs/IDs; the command makes no AWS calls. It does not guess resource IDs, generate service credentials or install IAM policies.

The BankingTerraformProvisioner permissions family uses stage-specific customer-managed policy documents rather than one over-quota policy. IAM uses BankingTerraformProvisioner-IamPrerequisites both as the bounded role grant and the managed STS cap. The VPC seed uses BankingTerraformProvisioner-VpcSeed and records verified VPC/default-SG IDs in native platform state. Platform uses its three split caps, each with an approved canonical digest in PLATFORM_POLICY_REVIEW_JSON. Data grants are separate per environment; the existing dev data workflow keeps its reviewed BankingReleasePlatformPhase6Session cap. Publish only the finalized currently authorized stage, checking attachment and inline quotas.

The AWS service authorization snapshot was retrieved on 13 October 2026 UTC from AWS's public servicereference.us-east-1.amazonaws.com endpoint. It contains relevant action/resource metadata and source URLs, not any private account state. Run `python scripts/infra/validate-provisioner-policies.py` for offline action/resource validation. Live authorization still depends on the actual identity grants, session cap, boundary, SCP/RCP and resource policies. Simulation cannot replace administrator authorization.
